# 前端完整产品需求（FRONTEND_PRD）V1.1

## 1. 产品定位、范围与导航
面向企业内部员工、审批人、采购人员、管理员及技术观察者。桌面优先（1440、1280、1024px），移动端保证基本查询/审批可用；技术画布可提示在桌面查看。仅借鉴参考截图的视觉风格，不复制其业务信息架构。最终页面结构由本产品业务决定。

**角色**：EMPLOYEE（员工）、APPROVER（审批人）、PROCUREMENT（采购人员）、ADMIN（管理员）、TECH_ADMIN（技术管理员）。同一用户可具备多个角色；后端为权限真值来源。TECH_ADMIN 只能诊断和受控测试工具，不能因技术权限自动获得审批/采购写权限。

**导航/路由表**（隐藏无权菜单不等于后端授权）：

| 页面/路由 | 核心内容 | 权限 | 优先级 |
|---|---|---|---|
| `/login` | 账号密码、登录错误 | 未登录 | P0 |

| `/procurements` | 我的采购申请/授权采购列表 | 已登录 | P0 |

## 2. 通用应用框架
- 应用框架可使用侧栏+顶栏，但不强制照搬截图布局。导航可折叠；面包屑按业务页面显示；头像菜单含个人资料与退出。
- 统一内容最大宽度约 1440px；聊天和工作流视图可占满可用宽度；表格页面提供搜索、分页、排序、筛选、清空筛选。
- 统一组件：`AppShell`、`PageHeader`、`DataTable`、`StatusBadge`、`ConfirmDialog`、`EmptyState`、`ErrorState`、`LoadingSkeleton`、`PermissionGate`、`SourceCitation`、`RunTimeline`、`MoneyDisplay`。
- 全局 toast 用于短反馈；重要失败保留页面内可追踪提示；提交按钮有 loading/禁用；分页和筛选状态同步 URL query。
- 页面跳转不丢失未保存表单：有脏数据时弹确认；刷新后以服务端持久化数据为准。

## 3. 登录与工作台
**登录**：用户名（必填）、密码（必填），登录失败统一提示不暴露账号是否存在；成功跳转原目标页或 `/`；过期登录返回登录页，保留安全的回跳地址；无权限显示 403。
**工作台**：欢迎信息、我的待办审批数（有 APPROVER 时）、我的采购单状态统计、最近会话/运行、快捷发起采购；数值来自真实 API 或明显标识的演示种子数据，禁止硬编码假统计。卡片点击必须跳转对应筛选结果。数据无权限时不展示。

## 4. AI 助手 `/assistant`
- 三个可折叠区域：会话导航、消息主区、任务详情/引用侧栏；窄屏优先消息主区。
- 会话：新建、切换、重命名、归档（可恢复）、搜索；按更新时间排序；会话所有权服务端校验。
- 输入：多行文本、发送、停止生成；空输入禁用；长度上限 4000 字符；附件上传只通过知识库授权入口，不直接混入聊天工具执行。
- 消息：用户/助手、时间、状态（发送中/流式中/完成/失败）、复制、重试；渲染 Markdown 必须净化 HTML，禁用不安全脚本。
- 流式：显示文本增量、节点开始/结束、工具状态、等待确认、完成/失败；断线可重新获取最终状态，不重复触发采购写操作。
- 结构化采购草稿：`category`、`item_description`、`quantity`、`unit_price_limit`、`total_budget`、`purpose`、`priority`、`notes`；缺失字段明确标注；用户可编辑、确认、取消；未经确认不得写入正式采购申请。
- RAG 引用卡：文件名、页码（可用时）、片段摘要、可点击定位；无证据时明确提示，不得展示伪造制度条款。
- 工具执行卡：工具名、阶段状态、耗时、脱敏摘要、错误/重试提示；员工只见业务级状态，技术角色可通过链接进入运行中心。
- 采购方案卡：候选商品、数量、单价、总价、库存、来源、风险；金额后端计算；点击“创建草稿”/“提交审批”必须按业务状态校验和明确确认。
- 人工审批等待卡：显示当前审批人角色、审批进度和待办状态；申请人不得看到审批按钮。
- 异常：LLM 无响应/超时、无制度证据、工具不可用、预算超限、SSE 断线、会话过期，分别展示可理解提示与安全重试入口。

## 5. 知识库 `/knowledge`
- 文档列表：文件名、格式、大小、上传者、上传时间、状态（PENDING/INDEXING/READY/FAILED）、失败原因摘要、操作。
- 上传：仅 PDF/TXT/MD；单文件默认最大 20MB（可配置），一次最多 10 个；后端校验 MIME/扩展名/大小；重复内容提示已存在；支持进度与失败重试。
- 文档详情：元信息、分块数量、可见片段、页码、索引版本、最近错误；支持重新索引（管理员）、删除（二次确认）。
- 检索测试：问题、top_k（1~10）、返回片段、相关分数（如后端支持）、来源；区分“未检索到”和“服务失败”；未就绪文档不进入检索。
- 权限：员工只能访问授权库，管理员可管理上传/删除；无权文档不得在搜索结果中泄漏名称或内容。

## 6. 采购申请 `/procurements`
- 列表字段：申请编号、标题、申请人、品类、数量、预算、状态、创建/更新时间；筛选状态、日期、关键字；按权限显示本人/授权数据。
- 新建/编辑：标题、品类、商品描述、数量（正整数）、单价上限（正金额）、派生总额（只读，数量×单价上限，服务端最终计算）、用途、优先级、备注；当前版本不提供独立总预算限制。
- 详情：需求信息、候选方案（价格/库存/来源/时间）、制度引用、审批链、状态时间线、关联 `run_id`、操作审计。
- 状态按钮：DRAFT 可编辑/提交/取消；PENDING_APPROVAL 只读；REJECTED 只读（重新提交作为后续需求，不在 MVP）；APPROVED 可由采购人员转 ORDERED；ORDERED→RECEIVED→CLOSED 仅采购人员操作。
- 提交：弹窗展示关键金额和审批链预览，确认后提交；失败保持原数据和错误提示；禁止重复提交。

## 7. 审批 `/approvals`
- 待办/已处理双标签；列表：申请编号、申请人、金额、当前级别、提交时间、状态；支持过滤。
- 详情：申请明细、采购方案、引用制度、审批历史、当前步骤；批准须明确确认；驳回必须输入 5~500 字原因。
- 每次操作携带 `Idempotency-Key`；处理中禁用按钮；重复请求返回同一业务结果；若已被他人处理，提示刷新。
- 自审被后端拒绝；技术管理员不因此获得审批权；审批前后状态由服务端返回决定。

## 8. 库存、供应商与管理员
- 库存：SKU、品类、型号、可用数量、参考单价、更新时间；员工只读，ADMIN 可维护；负库存禁止。
- 供应商：名称、启用状态、报价商品、单价、币种、报价时间；PROCUREMENT/ADMIN 维护；演示数据须标记 `mock/demo`。
- 审批规则：阈值区间、级别、审批角色/具体人员、启用状态；编辑前检查冲突、重叠和缺口；规则缺失时提交失败并提示管理员配置。
- 用户：用户名、部门、角色集合、启用状态；不能直接显示密码哈希；管理员重置操作需确认并审计。

## 9. Workflow / MCP / Harness 技术页面
**Workflow 运行列表**：run_id、业务单号、开始/结束时间、状态、耗时；详情以节点图 + 右侧详情面板呈现真实执行路径；节点状态 `NOT_STARTED/RUNNING/SUCCEEDED/FAILED/WAITING/SKIPPED`，点击节点显示输入/输出摘要、错误码、耗时、时间线。默认只读，不提供任意拖拽修改线上工作流。
**MCP 工具中心**：Server 名称、传输类型、连接状态、工具列表、Schema、授权范围、最近调用；只允许测试白名单只读工具；带副作用的工具禁止直接试运行，需通过授权业务流程。
**Harness 运行中心**：按 run_id、用户、状态、日期过滤；展示执行步数、工具调用、重试、超时、策略拒绝、错误信息和耗时；输入输出必须脱敏；展示 token/成本仅在提供方真实返回时，缺失显示“未提供”，不可估算成真实值。

## 10. 通用状态、可访问性与验收
- 每个页面必须具备 Loading、Empty、Error、Success 四态；权限不足 403；资源不存在 404；冲突 409；限流 429；服务失败可重试只读请求。
- 表单客户端校验用于体验，后端校验为准；状态标签有文字，不仅靠颜色；可键盘操作；对话输入、弹窗、表格有可访问标签。
- API 数据通过统一 client/typed DTO 读取；禁止组件内硬编码演示数据冒充 API。
- P0 页面端到端验收以 `docs/ACCEPTANCE_CRITERIA.md` 为准；P1 需有真实运行数据和 Mock 可复现轨迹。
