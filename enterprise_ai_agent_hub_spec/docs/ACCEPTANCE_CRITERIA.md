# 功能、工程与安全验收标准 V1.1

## 1. 验收原则
验收以可运行功能和真实测试记录为准，禁止仅凭页面截图、Mock 假统计或 AI 自述判定完成。Mock 可用于复现业务流程，但必须标注演示模式。每个用例记录前置数据、操作、预期、实际、证据、结果。

| ID | 场景 | 验收条件 | 优先级 |
|---|---|---|---|
| AC-01 | 认证 | 未登录访问受保护 API 返回 401；无权返回 403；过期 token 不可使用 | P0 |
| AC-02 | 角色/资源 | 员工不能查看他人采购单、会话、私有知识文档；TECH_ADMIN 不可审批 | P0 |
| AC-03 | 需求解析 | “采购10台笔记本，每台6000元”解析 quantity=10、unit_price_limit=6000.00；缺用途会追问 | P0 |
| AC-04 | 草稿确认 | AI 不经用户确认不得持久化采购申请；编辑后的字段以服务端校验结果为准 | P0 |
| AC-05 | 文档索引 | 上传合法 PDF/TXT/MD 可进入 READY；重复上传去重；错误格式/超限被拒 | P0 |
| AC-06 | RAG 引用 | 回答引用真实文档片段及可用页码；无命中明确无依据；无权限内容不泄露 | P0 |

| AC-14 | 工作流可视化 | 节点状态、执行路径、暂停/恢复来自真实 run 数据；历史 run 可回看 | P1 |

| AC-17 | 前端视觉 | 只借鉴截图视觉语言，不复制其业务内容；1440/1280/1024/390 宽度检查 | P0 |
| AC-18 | 通用交互 | Loading/Empty/Error/Success、表单校验、确认弹窗、分页、键盘焦点完整 | P0 |
| AC-19 | 安全 | 不泄露密钥；不允许任意 shell/SQL；RAG/MCP prompt injection 不可越权 | P0 |
| AC-20 | 可部署 | 无 Key Mock 模式可启动、迁移、seed、运行核心端到端演示 | P0 |

## 2. 自动化测试最低要求
- 单元：意图 schema、Decimal、审批阈值、状态机、权限策略、Harness 限额。
- API 集成：JWT、所有权、上传、索引、采购提交、审批事务/幂等、SSE 事件序列。
- 端到端：员工发起→检索制度→查库存报价→确认→提交→审批→采购履约；覆盖拒绝分支。
- 前端：关键表单校验、路由权限、错误态、对话 SSE 状态、审批按钮防重复。
- 安全：越权读取、工具注入、日志脱敏、非法文件上传、密钥扫描。
- CI/本地：ruff、pytest、前端 lint/typecheck/build、docker compose config、迁移检查；不能执行则标记 BLOCKED 而非 PASS。

## 3. 阶段完成定义（DoD）
每阶段须具备：代码可运行、与本阶段 API/DB/前端需求对应、迁移可复现、测试实际执行并通过、README 更新、阶段状态报告有证据。没有实际验证不得标 DONE。项目最终交付必须包括操作演示、测试报告、已知限制和 Mock 标记。
